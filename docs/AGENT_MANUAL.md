# Узел: собрать, подключить, обновлять

Мануал оператора сети. Три вещи в жизни узла и ничего лишнего. Что там внутри —
[WORKER_RUNTIME.md](WORKER_RUNTIME.md), почему обновление устроено именно так —
[WORKER_UPDATE.md](WORKER_UPDATE.md).

---

## 0. Один раз: релизный ключ

**Сделать до первой сборки образа.** Публичная половина ключа вшивается в
образ и решает, чей код имеет право запуститься на чужой машине. Образ,
собранный без неё, **никогда не примет обновление** — состояние безопасное, но
для уже розданных узлов необратимое: чтобы дать им ключ, придётся просить
владельцев перезапустить контейнер руками.

```bash
pip install cryptography          # единственная зависимость скрипта
python scripts/sign_release.py keygen --out agent-release.key
```

Кладёт приватную половину в `agent-release.key`, публичную — в
`agent/loom_launcher/release_key.pub`.

**Приватную половину надо сохранить в надёжном месте.** Потеряется — обновлять
парк будет нечем: подписать новый релиз никто не сможет, а узлы принимают
только подписанное этим ключом. Единственный выход тогда — собрать образ с
новым ключом и просить каждого владельца перезапустить контейнер руками, то
есть ровно то, от чего обновление по сети избавляет.

**Приватный ключ не должен попасть на оркестратор, в репозиторий и в CI,
который может запустить кто угодно.** Смысл разделения: захваченный
оркестратор сможет назвать любой из уже подписанных нами релизов — плохо, — но
не запустить новый код на каждой машине парка. Если ключ утёк, это перестаёт
быть правдой.

Ключ в `.gitignore`, и это не небрежность: у каждого, кто поднимает свой Loom,
он должен быть свой.

## 1. Собрать образ

```bash
scripts/build_agent.sh              # для этой машины, локально
scripts/build_agent.sh --push       # amd64 + arm64, в реестр
```

Имя меняется через `LOOM_AGENT_IMAGE` и `LOOM_AGENT_TAG`.

Что внутри: агент, пусковой слой, p2p-стек и NVML. Ни torch, ни vLLM, ни
CUDA-тулкита — всё, что нужно задаче, разворачивается в её каталоге при
запуске. Поэтому образ маленький и меняется редко, а это важно: **пересборка
образа — единственный вид обновления, который владелец машины делает руками.**

Скрипт предупредит, если `release_key.pub` отсутствует. Предупреждение стоит
читать: собранный так образ работать будет, а обновляться — нет.

## 2. Подключить машину

### Выдать ключ

В панели на `:8080`, вкладка Keys, или запросом:

```bash
curl -s http://<оркестратор>:8000/admin/keys -X POST \
  -H "X-Loom-Admin-Token: $LOOM_ADMIN_TOKEN" \
  -H 'Content-Type: application/json' -d '{"label":"машина Миши"}'
```

В ответе — готовая команда. Владелец выполняет **одну строку** и больше не
вводит ничего: адрес оркестратора уже внутри ключа.

```bash
docker run -d --gpus all --restart unless-stopped --network host \
  -v loom-data:/var/lib/loom \
  gihpee/loomagent --key loom_...
```

### Что в этой команде не косметика

**`--network host`.** Без него p2p-порт остаётся портом контейнера, а не хоста,
и исходящие пакеты транслируются ещё раз на выходе. Пробивание NAT из такой
позиции не работает никогда — узел останется рабочим, но все сообщения к
соседям пойдут через оркестратор, вдвое длиннее.

**`-v loom-data:/var/lib/loom`.** Здесь каталоги задач, кэш окружений и
нагрузки агента. Без тома кэш пересобирается после каждого перезапуска, а
обновление агента рестарт не переживает — узел откатится к версии из образа.

**`--restart unless-stopped`.** Иначе узел исчезает после первой перезагрузки
машины, и владелец об этом не узнает.

**`--gpus all`.** Агент сам разложит задачи по картам. Отдать только часть —
`--gpus '"device=0,1"'`; тогда на этой машине можно поднять второй агент на
остальные, и они не столкнутся: имя узла получит суффикс по видимым картам.

Два агента на одной машине **могут делить один том**, и это полезно: кэш
окружений собирается один раз на двоих, а торрент из двух параллельных
установок torch — не то, чем стоит занимать канал владельца. Сборка защищена
файловой блокировкой; проигравший гонку берёт чужой результат вместо своего.

### Проверить

Узел появляется в админке на вкладке Nodes за несколько секунд. В его логе:

```
hardware: device=cuda gpu=NVIDIA GeForce RTX 4090 x2 vram_free=47.3GB ... (nvml)
tasks will run as loom-task on 2 GPU(s)
registered as <имя узла>
```

Если вместо второй строки:

```
this node will REFUSE every task until it can run them as a separate user
```

— агент запущен не от root либо в образе нет пользователя `loom-task`. Узел
**виден и здоров на вид**, но не возьмёт ни одной задачи. Так задумано:
запускать чужой код от пользователя агента — значит отдать ему ключ узла и
файлы соседних задач.

### Остановить

```bash
docker stop <контейнер>
```

Агент получит SIGTERM, **снимет идущие задачи** и закроет стрим — оркестратор
узнает причину сразу, а не по таймауту молчания.

Задачи здесь именно снимаются, а не дожидаются: у `docker stop` есть свои
десять секунд до SIGKILL, и притворяться, что за них успеет доработать
обучение, было бы враньём. Дожидаются задачи **при обновлении** — там время
есть, и оно тратится (см. ниже про слив).

Если на узле идёт чужой долгий расчёт, лучше сначала снять с него работу
через админку и дать ей закончиться, а останавливать контейнер потом.

## 3. Обновлять

Обновляется **не образ**, а нагрузка внутри него. Владелец машины не делает
ничего.

### Выпустить

```bash
git pull                          # подписывается ТО, что лежит в этом рабочем дереве
python scripts/sign_release.py sign --key agent-release.key --version 0.3.0
```

Печатает версию, sha256, подпись и готовый `curl` для публикации.

Скрипт пакует `agent/loom_agent` **из текущего рабочего дерева** — не из
реестра, не из ветки по имени. Что в нём лежит, то и уедет на все машины
парка, поэтому подписывать стоит с чистого дерева на нужном коммите.

В архив попадает только агент. Пусковой слой (`agent/loom_launcher`) в него
намеренно не входит: он живёт в образе и по сети не обновляется — сломанный
запускатель, приехавший таким путём, нельзя было бы починить, прислав ещё
один. Подписывается
манифест целиком, а не только архив: подпись только байтов позволила бы подать
настоящую старую нагрузку под новым номером версии.

Версия должна быть **больше** текущей. Релиз годовой давности подписан
по-прежнему верно, и его установка — это способ вернуть исправленную
уязвимость; узлы такое отвергают.

### Опубликовать

Панель, вкладка Release — манифест и архив. Или тем
`curl`, который напечатал скрипт.

**Публикация не начинает выкатку.** Опубликованный релиз стоит на 0%.

### Выкатить ступенями

На той же вкладке: 10% → 25% → 50% → весь парк. Между ступенями — карта
версий: сколько узлов уже на новой, сколько в текущей волне.

Волна выбирается по имени узла, а не жребием: узел остаётся в той же волне при
каждом переподключении. Иначе он обновлялся бы, через минуту снова попадал в
«ещё не пора» и никогда не устоялся.

**Ступень переводится руками.** «Зарегистрировался» и «работает» — не одно и
то же, и автопереход разносил бы сломанную сборку уверенно.

### Что происходит на узле

```
оркестратор объявляет желаемую версию (в ответе на регистрацию)
    │
агент качает нагрузку и останавливается
    │  перед этим сливается: новую работу не берёт, идущую доводит до конца
пусковой слой проверяет подпись
    │  не сошлась — не ставит, узел остаётся на рабочей версии
устанавливает и переключает символьную ссылку
    │
новый агент регистрируется и помечает себя рабочим
```

Обновление — **не рассылка, а объявление**: узел, выключенный неделю, догонит
сам при следующем подключении, новый придёт сразу правильным.

### Если сборка плохая

Две сети защиты, обе на узле:

**Откат.** Три быстрых падения версии, которая **ни разу не регистрировалась**,
— и пусковой слой возвращает предыдущую. Решение принимается на узле, никого не
спрашивая: связь с оркестратором может быть ровно тем, что новая версия
сломала. Версия, которая раньше работала, не откатывается — значит сломалось не
новое, и подмена версии спрятала бы настоящую причину.

**Остановка выкатки.** Кнопка «stop rollout» в админке. Узлы, уже обновившиеся,
остаются на новой версии: забрать её назад — значит опубликовать более старую,
а это узлы отвергают. Правильный путь вперёд — выпустить исправление с номером
выше.

### Когда всё-таки нужен образ

Пересборка и ручной перезапуск нужны, если поменялось то, чего в нагрузке нет:

- версия Python или системные библиотеки образа;
- сам пусковой слой;
- релизный ключ.

Это редко — потому образ и держат тонким. В админке видно, кто на какой версии
агента; версию образа узел сообщает там же.

## 4. Если что-то не так

| симптом | куда смотреть |
|---|---|
| узел не появился | `/admin/connect` — `severity` и `self_check`; открыт ли GRPC-порт снаружи |
| узел есть, задач не берёт | лог агента при старте: он называет причину одной строкой |
| всё идёт через оркестратор | лог агента про p2p: он различает symmetric NAT, отсутствие реле и запуск без `--network host` |
| задача падает сразу | `/admin/tasks/<id>/logs` — это stdout самой задачи |
| обновление не приезжает | образ собран без `release_key.pub`, либо узел вне текущей волны |
| узел откатился сам | новая версия ни разу не зарегистрировалась; смотреть её логи до отката |
