# NOTICE — код, заимствованный из Parallax

Loom заимствует и адаптирует код проекта **Parallax**
(https://github.com/GradientHQ/parallax, arXiv:2509.26182). Локальный
read-only источник: `../dllmi/parallax/`. Этот файл дублирует (но не заменяет)
inline-атрибуцию в шапке каждого заимствованного модуля.

Заимствованного стало меньше: планировщик Phase-1/Phase-2 и роутер удалены
вместе со старой архитектурой. vLLM-адаптер возвращается по частям — ради
continuous batching, которого у собственного исполнителя нет и не будет.

| `payloads/loom_stage/loom_stage/loader.py` | `src/parallax/server/shard_loader.py` (загрузка среза слоёв, ремап ключей на локальные индексы) + `src/parallax/vllm/model_runner.py` (роли is_first_peer/is_last_peer) | Реализация на torch/transformers вместо MLX и вместо наследования vLLM `GPUModelRunner`: нужен device-agnostic исполнитель (cpu/cuda), проверяемый без GPU-стенда и не привязанный к внутренним API конкретной версии vLLM. Ответ на чужой батч выбрасывается по `batch_id`: опоздавший, принятый за свой, сдвигает каждый следующий токен на шаг. | `payloads/loom_stage/loom_stage/vllm_runner.py` | `src/parallax/vllm/model_runner.py` (`ParallaxVLLMGroupCoordinator` — ответ «первый/последний ранг» по диапазону слоёв; `load_model` — подмена `get_pp_indices` на время загрузки; порядок поднятия из `initialize_vllm_model_runner`) | Спецификация KV-кэша берётся снятием cudagraph-обёртки, а не запасным путём первоисточника (посчитать форму по конфигу модели): неверная форма кэша не падает, она портит внимание — ответы остаются связными и становятся неправильными. Решения (роль стадии, границы среза) вынесены в чистые функции и проверяются без vLLM и без карты. Подмена `get_pp_indices` возвращается на место через `try/finally` в любом случае: она глобальная, и оставленная после неудачи портит следующую загрузку. Негодный срез отвергается, а не берётся молча — иначе стадия считает чужие слои и отвечает связной чушью, нигде не падая. |

Добавлена сверка числа собранных слоёв с запрошенным: подмена `get_pp_indices` — единственное, что удерживает vLLM от сборки всей модели, и её молчаливый провал даёт стадию, которая ест всю карту и не говорит ни слова. |
| `payloads/loom_stage/loom_stage/vllm_batch.py` | `src/parallax/vllm/batch_info.py` (`form_vllm_batch_prefill`, `form_vllm_batch_decode`, `_build_vllm_request`, `release_vllm_request` — конструирование `SchedulerOutput` в обход планировщика vLLM) | Без LoRA и мультимодальности: нечем проверить. Состав батча приходит одной структурой `Sequence` — наш тип, потому что он едет между стадиями, и привязывать провод к внутренностям движка значило бы менять протокол вместе с его версией.
